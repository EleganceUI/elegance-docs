In Elegance you don't animate a property from one value to another. You change your state, and
say that the change should be animated. Everything the change affects then moves smoothly to where
it ends up: colors, fills, strokes, opacity, offsets, sizes, and positions. Views that appear or
disappear because of it come and go with a transition.

## Animating a change

Wrap the change in `with_animation`:

```cpp
Button("Toggle", [=] {
    with_animation(Animation::spring(), [&] { expanded = !expanded(); });
});
```

```rust
# let expanded = State::new(false);
Button("Toggle", move || with_animation(Animation::spring(0.5, 0.825), || expanded.toggle()))
```

Everything that changes because of what you did inside it animates, including views moving and
resizing, and views appearing and disappearing.

## Animating whenever a value changes

Sometimes it's simpler to say "this view always animates when this value changes", wherever the
change comes from. That's what `.animation(animation, value)` does:

```cpp
Circle()
    .fill([=] { return on() ? Color::hex(0x9ECE6A) : Color::hex(0x565F89); })
    .offset([=] { return on() ? 40.f : 0.f; }, 0.f)
    .animation(Animation::spring(0.35, 0.7), on);
```

```rust
# let on = State::new(false);
Circle()
    .fill(move || if on.get() { Color::hex(0x9ECE6A) } else { Color::hex(0x565F89) })
    .offset(move || if on.get() { 40.0 } else { 0.0 }, 0.0)
    .animation(Animation::spring(0.35, 0.7), on)
```

The value can be a state, a closure, or a plain value; Elegance compares it to its previous value
to see whether it changed.

## Curves and springs

An animation's *curve* decides how it gets from start to finish:

```cpp
Animation::linear(0.25)
Animation::ease_in(0.25)
Animation::ease_out(0.2)
Animation::ease_in_out(0.35)
Animation::spring()              // settles in about half a second
Animation::spring(0.35, 0.6)     // quicker and bouncier
Animation::smooth(0.4)           // a spring that doesn't overshoot
Animation::ease_out(0.2).delay(0.1)
```

```rust
let curves = [
    Animation::linear(0.25),
    Animation::ease_in(0.25),
    Animation::ease_out(0.2),
    Animation::ease_in_out(0.35),
    Animation::spring(0.5, 0.825), // settles in about half a second
    Animation::spring(0.35, 0.6),  // quicker and bouncier
    Animation::smooth(0.4),        // a spring that doesn't overshoot
    Animation::ease_out(0.2).delay(0.1),
];
```

Times are in seconds. Springs feel the most natural for things people move or toggle. A spring's
first number is roughly how long it takes to get there; the second is how much it bounces, where 1
means it settles without overshooting and lower numbers bounce more. They mean the same as in
SwiftUI.

### Your own curve

`Animation::custom` takes an easing function. It's called with how much of the time has passed,
from 0 to 1, and returns how far along the animation should be, 0 at the start and 1 at the end:

```cpp
// Ease-out cubic over 0.3 s
Animation::custom([](double t) { return 1 - std::pow(1 - t, 3); }, 0.3)

// Overshoots a little before settling
Animation::custom([](double t) {
    const double c = 1.70158;
    return 1 + (c + 1) * std::pow(t - 1, 3) + c * std::pow(t - 1, 2);
}, 0.4)
```

```rust
// Ease-out cubic over 0.3 s
let cubic = Animation::custom(|t| 1.0 - (1.0 - t).powi(3), 0.3);

// Overshoots a little before settling
let back = Animation::custom(|t| {
    let c = 1.70158;
    1.0 + (c + 1.0) * (t - 1.0).powi(3) + c * (t - 1.0).powi(2)
}, 0.4);
```

The function can go below 0 or above 1 to undershoot or overshoot; when the time is up, the value
lands where it's going regardless. It runs every frame, so keep it quick.

<Lang only="cpp">

`Animation::timing_curve(x1, y1, x2, y2, duration)` is a cubic Bézier curve, like CSS's
`cubic-bezier()`, handy when you're matching a design or a web animation.

</Lang>

If something changes again while it's still animating, the new animation starts from wherever it
is at that moment, so nothing jumps.

## Views coming and going

When a view is added or removed during an animated change, its *transition* decides how it enters
and leaves. Unless you choose one, it fades.

```cpp
If(shown,
   Banner().transition(Transition::move(Edges::top).combined(Transition::opacity())));

ForEach(items, &Item::id, [](const Item& item) {
    return Row(item).transition(Transition::scale(0.8f).combined(Transition::opacity()));
});
```

```rust
# #[derive(Clone, PartialEq)] struct Item { id: i64, name: String }
# let (shown, items) = (State::new(true), State::new(Vec::<Item>::new()));
if shown.get() {
    Text("Saved").transition(Transition::move_edge(.top).combined(Transition::opacity()))
}

ForEach(items, id: |i| i.id) { item in
    Text(item.name.clone()).transition(Transition::scale(0.8).combined(Transition::opacity()))
}
```

| Transition | What it does |
| --- | --- |
| opacity | fades in and out (the default) |
| scale | grows from, and shrinks to, a fraction of its size, around its middle or a corner or edge you pick |
| offset | moves in from somewhere nearby |
| move | slides in from beyond one of its edges |
| slide | comes in from the leading edge, leaves toward the trailing edge |
| identity | appears and disappears at once |
| asymmetric | one transition in, another out |

Combine transitions with `.combined(...)`, as above.

## Layout moves too

Positions and sizes animate along with everything else: during an animated change, views glide to
their new place. Reordering a list, for example, slides each row to where it now belongs.

For a part of the interface that should snap into place instead, use `.animates_layout(false)`.
Colors, opacity, and transitions inside it still animate.

## Repeating animations

<Lang only="rust">

The C++ API can repeat an animation a number of times, or forever, for loaders and attention
effects. The Rust bindings don't have repeating animations yet.

</Lang>

<Lang only="cpp">

An animation can play several times, or keep going for as long as the view is on screen: loading
indicators, a pulsing badge. `repeat_count(n)` plays it `n` times, and `repeat_forever()` keeps
going until the value changes or the view goes away. By default every other repeat runs backward,
so the animation goes back and forth; pass `false` to start over from the beginning each time
instead, like a spinner turning.

Combined with `on_appear`, which runs when a view appears, this is all a loader needs. Each dot
here starts a little further along with a negative delay, so they chase each other:

```cpp
View OrbitingDots() {
    const State<bool> spinning(false);
    const auto dot = [=](Color color, double ahead) {
        return Circle()
            .fill(color)
            .frame(12, 12)
            .offset(0, -6)
            .frame(72, 72, Alignment::top)
            .rotation_effect([=] { return spinning() ? 360.f : 0.f; })
            .animation(Animation::timing_curve(0.55, 0.1, 0.45, 0.9, 1.4).delay(-ahead).repeat_forever(false),
                       spinning);
    };
    return ZStack(Circle().stroke(Color::white.opacity(0.12f), 2),
                  dot(Color::hex(0xFF6B3D), 0),
                  dot(Color::hex(0xFFD84D), 0.12),
                  dot(Color::hex(0x7EA0FF), 0.24))
        .frame(72, 72)
        .accessibility_label("Loading")
        .on_appear([=] { spinning = true; });
}
```

A negative delay starts an animation partway through, as in CSS: `delay(-0.12)` begins where it
would be 0.12 seconds in.

</Lang>
