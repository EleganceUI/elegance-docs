These use the system's own dialogs and services, so they look and behave the way people expect on
each platform. Use them on the UI thread while the app is running. Their callbacks run on the UI
thread too, so they can change state.
<Lang only="rust" inline>In Rust, they're in `elegance::desktop`, which the prelude doesn't include.</Lang>

## File dialogs

```cpp
choose_files({.filters = {{"Images", {"png", "jpg", "jpeg"}}}, .multiple = true},
             [=](std::vector<std::filesystem::path> files) {
                 photos.update([&](auto& list) { list.insert(list.end(), files.begin(), files.end()); });
             });

choose_save_file({.filters = {{"Text", {"txt"}}}, .name = "notes.txt"},
                 [=](std::optional<std::filesystem::path> path) {
                     if (path) {
                         save_notes(*path);
                     }
                 });

choose_folders({}, [=](std::vector<std::filesystem::path> folders) { /* ... */ });
```

```rust
use elegance::desktop::*;

# use std::path::PathBuf;
# let photos = State::new(Vec::<PathBuf>::new());
# let save_notes = |_: PathBuf| {};
choose_files(
    OpenFilesOptions { filters: vec![FileFilter::new("Images", &["png", "jpg", "jpeg"])], multiple: true, ..Default::default() },
    move |files| photos.write().extend(files),
);

choose_save_file(
    SaveFileOptions { filters: vec![FileFilter::new("Text", &["txt"])], name: "notes.txt".into(), ..Default::default() },
    move |path| {
        if let Some(path) = path {
            save_notes(path);
        }
    },
);

choose_folders(ChooseFolderOptions::default(), |folders| { /* ... */ });
```

The dialogs open over the active window, and your app keeps running while they're open. The
callback gets what was chosen, or nothing if people cancelled. A filter with no extensions means
all files, and `directory` chooses where the dialog starts. The save dialog asks about replacing a
file that's already there, but doesn't create the file; that's up to you.

## Notifications

```cpp
notify({.title = "Export finished", .body = "Saved 12 photos", .on_click = [=] { show_folder(); }});
```

```rust
# use elegance::desktop::*;
# let show_folder = || {};
notify(Notification::new("Export finished", "Saved 12 photos").on_click(show_folder));
```

The callback runs when people click the notification. Notifications also stay in the system's
notification center, and people can turn them off in its settings.

<Aside>
On macOS, notifications need your app to be an app bundle, which
<Lang only="cpp" inline>`elg_add_application` makes.</Lang><Lang only="rust" inline>a tool such as [cargo-bundle](https://crates.io/crates/cargo-bundle) can make.</Lang>
Run as a bare executable, notifications are only written to the log. macOS asks people the first
time your app sends one.
</Aside>

## Tray icon

A `TrayIcon` puts an icon with a menu in the system tray: the menu bar on macOS, the notification
area on Windows. It's shown for as long as you keep it, so keep it somewhere that lasts, such as
`main`:

```cpp
std::optional<TrayIcon> tray;

app.window({.title = "Sync"}, [&] {
    tray.emplace(TrayIconOptions{
        .icon = {.file = "assets/tray.png"},
        .tooltip = "Sync",
        .menu = {{.title = "Pause syncing", .checked = false, .toggled = [=](bool on) { paused = on; }},
                 {}, // a separator
                 {.title = "Quit", .action = [&] { app.quit(); }}},
    });
    return SyncView();
});
```

```rust
use elegance::desktop::{TrayIcon, TrayIconOptions, TrayMenuItem};

# #[component] fn SyncView() -> impl IntoView { elg! { Text("Sync") } }
fn main() -> Result<std::process::ExitCode, Error> {
    let app = App::new();
    let quit = app.handle();
    let paused = State::new(false);

    let _tray = TrayIcon::new(TrayIconOptions {
        icon: ImageSource::file("assets/tray.png"),
        tooltip: "Sync".into(),
        menu: vec![
            TrayMenuItem::check_box("Pause syncing", false, move |on| paused.set(on)),
            TrayMenuItem::separator(),
            TrayMenuItem::new("Quit", move || quit.quit()),
        ],
    })?;

    app.window(WindowDesc::new("Sync"), SyncView).run()
}
```

Menu items can run an action, be a check box, be turned off, or open a submenu.
`set_tooltip` and `set_menu` change them later. Without an icon, the tray shows a dot in your
theme's accent color.

## The menu bar

`App::menu_bar` gives your app menus: at the top of the screen on macOS, and at the top of each
window on Windows and Linux. Items can have keyboard shortcuts, which work while the menu is
closed.

Give an item a *role* and it does the standard thing, with the standard title and shortcut, unless
you give it your own: `quit`, `about`, `settings`, the editing commands (`undo`, `cut`, `copy`,
`paste`, and so on, which go to the text field people are typing in), and the window commands. A
menu with the `app` role is the application menu on macOS, named after your app; elsewhere, its
items join the first menu.

```cpp
app.menu_bar({
    {.role = MenuRole::app, .submenu = {{.role = MenuRole::about}, {}, {.action = open_settings, .role = MenuRole::settings},
                                        {}, {.role = MenuRole::quit}}},
    {.title = "File", .submenu = {{.title = "New Note", .action = new_note, .shortcut = KeyboardShortcut{Key::n}},
                                  {.title = "Export…", .action = export_notes}}},
    {.title = "Edit", .submenu = {{.role = MenuRole::undo}, {.role = MenuRole::redo}, {},
                                  {.role = MenuRole::cut}, {.role = MenuRole::copy}, {.role = MenuRole::paste}}},
    {.title = "Window", .role = MenuRole::window, .submenu = {{.role = MenuRole::minimize}, {.role = MenuRole::zoom}}},
});
```

A shortcut uses the platform's main modifier unless you say otherwise: Command on macOS, Control
elsewhere. Calling `menu_bar` again while the app runs replaces the menus.

## The Dock and taskbar

Your app's icon in the Dock or taskbar can show how things are going while people are in another
app:

```cpp
set_badge("3");                         // a short label, like an unread count; nullopt removes it
set_progress(0.4);                      // a progress bar on the icon; nullopt removes it
set_progress(std::nullopt);
set_progress(0, ProgressState::indeterminate); // busy, without knowing how far along
request_attention();                    // bounce the Dock icon, or flash the taskbar button
```

`request_attention` does nothing while your app is in front. Pass `true` to keep asking until
people switch to it. On Linux, these work with launchers that support them, such as GNOME's Dash
to Dock and KDE's, and badges can only show numbers there.

</Lang>

<Lang only="rust">

The C++ API also has a menu bar (`App::menu_bar`), and can put a badge or a progress bar on your
app's icon in the Dock or taskbar. The Rust bindings don't have these yet.

</Lang>
