Most of an interface is built once and then just updates. Some parts come and go: an empty-state
message, a row for each message in an inbox, a details panel that opens. This page covers
showing views conditionally, repeating them for a collection, scrolling, and letting people select
rows.

## Showing a view conditionally

<Lang only="cpp">`If` shows one view while a condition holds, and another one (or nothing) otherwise:</Lang>
<Lang only="rust">Inside `elg!`, an `if` shows one view while a condition holds, and another one (or nothing) otherwise. It's reactive: the condition is checked again whenever a state it reads changes.</Lang>

```cpp
If([=] { return items().empty(); },
   Text("Nothing here yet"),
   ItemList(items));

If(show_details, Details()); // a State<bool> works as the condition
```

```rust
# let items = State::new(Vec::<String>::new());
# let show_details = State::new(false);
if items.read().is_empty() {
    Text("Nothing here yet")
} else {
    Text(move || format!("{} items", items.read().len()))
}

if show_details.get() {
    Text("Details")
}
```

<Lang only="rust">

`match` works the same way, for a value with more than two cases. Each arm is a view, and the
view is rebuilt when the value changes:

```rust
# #[derive(Clone, PartialEq)] enum Status { Loading, Failed(String), Ready }
# let status = State::new(Status::Loading);
match status.get() {
    Status::Loading => Progress(),
    Status::Failed(message) => Text(message).foreground_style(.danger),
    Status::Ready => Text("Ready"),
}
```

</Lang>

When the condition changes, the views of the old branch are removed, along with any state created
inside them, and the other branch is built. In a stack, the branch acts like a direct child of the
stack, and a branch with nothing in it takes no space.

If the change happens inside `with_animation`, the views come and go with their
[transition](../animation/#transitions), a fade unless you choose another.

## A view for each item

`ForEach` makes a view for each item in a collection. Each item needs a **key** that says which
item it is, so Elegance can tell items apart when the collection changes:

```cpp
ForEach(todos, &Todo::id, [](const Todo& todo) { return TodoRow(todo); })
```

```rust
# #[derive(Clone, PartialEq)] struct Todo { id: i64, title: String }
# let todos = State::new(Vec::<Todo>::new());
ForEach(todos, id: |t| t.id) { todo in
    Text(todo.title.clone())
}
```

The collection can be a fixed list, a state, a computed value, or a closure that returns one.
When it changes:

- items whose key and value are unchanged keep their views, including any state inside them;
- items whose value changed get new views;
- items that are gone are removed, and new items get views.

Keys are integers or strings<Lang only="cpp" inline> (or enums)</Lang>. A list of integers or strings can use the values as their own keys:

```cpp
ForEach(std::vector<std::string>{"Red", "Green", "Blue"}, [](const std::string& name) { return Text(name); })
```

```rust
ForEach(vec!["Red", "Green", "Blue"]) { name in
    Text(*name)
}
```

In a stack, the items are children of the stack, so they get its spacing and alignment.

<Aside type="tip">
<Lang only="cpp" inline>Give your item type an `operator==` (`= default` is enough). Without one, `ForEach` can't tell an item changed, and keeps its old view.</Lang>
<Lang only="rust" inline>Items need `Clone` and `PartialEq`: that's how `ForEach` tells an item changed and needs a new view.</Lang>
</Aside>

### Filtering and sorting

To show only some items, or show them in a different order, give `ForEach` a computed value:

```cpp
const auto visible = computed([=] {
    auto list = todos();
    std::erase_if(list, [&](const Todo& t) { return hide_done() && t.done; });
    return list;
});

ForEach(visible, &Todo::id, TodoRow)
```

```rust
# #[derive(Clone, PartialEq)] struct Todo { id: i64, title: String, done: bool }
# let todos = State::new(Vec::<Todo>::new());
# let hide_done = State::new(false);
let visible = computed(move || {
    todos.read().iter().filter(|t| !(hide_done.get() && t.done)).cloned().collect::<Vec<_>>()
});

elg! {
    VStack {
        ForEach(visible, id: |t| t.id) { todo in Text(todo.title.clone()) }
    }
}
```

## Scrolling

A `ScrollView` shows content that's bigger than the space it has, and scrolls it with the mouse
wheel, the trackpad, the scroll bars, and the keyboard:

```cpp
ScrollView(VStack({.alignment = HorizontalAlignment::leading}, rows...));
ScrollView({.axes = ScrollAxes::horizontal, .shows_indicators = false}, HStack(cards...));
```

```rust
ScrollView {
    VStack(alignment: .leading) { /* rows */ }
}
ScrollView(axes: .horizontal, shows_indicators: false) {
    HStack { /* cards */ }
}
```

The scroll view takes all the space it's offered, and lets its content be as long as it likes in
the direction it scrolls. When Tab moves focus to a view that's out of sight, the scroll view
brings it into view.

Scrolling behaves the way people expect on each platform. A scroll that starts over the page
keeps scrolling the page, even as a horizontal shelf passes under the pointer; Shift and the wheel
scroll sideways. On a Mac trackpad, content follows your fingers, glides on when you let go, and
stretches and springs back at the ends.

### Scrolling from code

Make a `ScrollPosition`, give it to the scroll view, and use it from anywhere:

```cpp
const auto position = ScrollPosition();

ScrollView({.position = position}, LazyVStack(ForEach(messages, &Message::id, MessageRow)));

Button("Newest", [=] { position.scroll_to_end(); });
Button("Top", [=] { position.scroll_to_top(); });
Button("Pinned", [=] { position.scroll_to(pinned_id()); }); // a ForEach key
```

```rust
# #[derive(Clone, PartialEq)] struct Message { id: i64, text: String }
# let messages = State::new(Vec::<Message>::new());
# let pinned_id = State::new(0_i64);
let position = ScrollPosition::new();

elg! {
    VStack {
        ScrollView(position: position.clone()) {
            LazyVStack {
                ForEach(messages, id: |m| m.id) { message in Text(message.text.clone()) }
            }
        }
        HStack {
            Button("Newest", { let position = position.clone(); move || position.scroll_to_end(true) })
            Button("Top", { let position = position.clone(); move || position.scroll_to_top(true) })
            Button("Pinned", move || position.scroll_to(pinned_id.get())) // a ForEach key
        }
    }
}
```

### Chat and logs

A scroll view that *sticks to the end* starts at the bottom, and stays there as content is added:
new messages, or images that finish loading. Scroll up even a little and it stops following, so
reading older messages isn't interrupted; scroll back to the bottom and it follows again.

```cpp
ScrollView({.sticks_to_end = true}, LazyVStack(ForEach(messages, &Message::id, MessageRow)));
```

```rust
# #[derive(Clone, PartialEq)] struct Message { id: i64, text: String }
# let messages = State::new(Vec::<Message>::new());
ScrollView(sticks_to_end: true) {
    LazyVStack {
        ForEach(messages, id: |m| m.id) { message in Text(message.text.clone()) }
    }
}
```

Lazy stacks also keep what you're looking at in place when rows above it change size or are
inserted, so loading older messages doesn't make the view jump.

## Long lists

A `VStack` builds every one of its children. For a long collection, use a `LazyVStack` (or
`LazyHStack`) inside a scroll view: it builds only the rows on screen or close to it, estimates the
size of the rest, and throws away rows that scroll far out of sight. It handles tens of thousands
of items.

```cpp
ScrollView(LazyVStack({.spacing = 4}, ForEach(messages, &Message::id, MessageRow)));
```

```rust
# #[derive(Clone, PartialEq)] struct Message { id: i64, text: String }
# let messages = State::new(Vec::<Message>::new());
ScrollView {
    LazyVStack(spacing: 4) {
        ForEach(messages, id: |m| m.id) { message in Text(message.text.clone()) }
    }
}
```

A lazy stack's content must be a `ForEach`. Rows that scroll away are destroyed, with any state in
them, so keep state that matters outside the rows.

### Lines between rows

There's no separate list view in Elegance: a list is a lazy stack in a scroll view, styled like
anything else. A `LazyVStack` can draw lines between its rows:

```cpp
ScrollView(LazyVStack({.spacing = 0, .separators = StackSeparators{.inset = 16}},
                      ForEach(contacts, &Contact::id, [](const Contact& c) {
                          return ContactRow(c).padding(EdgeInsets::symmetric(16, 10));
                      }))
               .background(ThemeColor::surface, RoundedRectangle(10)));
```

```rust
# #[derive(Clone, PartialEq)] struct Contact { id: i64, name: String }
# let contacts = State::new(Vec::<Contact>::new());
ScrollView {
    LazyVStack(spacing: 0, separators: StackSeparators::default().inset(16)) {
        ForEach(contacts, id: |c| c.id) { contact in
            Text(contact.name.clone()).padding(horizontal: 16, vertical: 10)
        }
    }
    .background_in(.surface, RoundedRectangle(10))
}
```

The separators can have their own color, thickness, and inset from the leading edge. Rows bring
their own padding and background; the stack only places them.

## Selecting rows

`.selection` on a stack over a `ForEach` makes its rows selectable. Bind it to an optional key for
one row at a time, or to a set of keys for several:

```cpp
const State<std::optional<int>> open;   // one row
const State<std::set<int>> chosen;      // any number of rows

ScrollView(LazyVStack(ForEach(mails, &Mail::id, MailRow))
               .selection(open.binding(), {.on_activate = [=](int id) { show(id); }}));
ScrollView(LazyVStack(ForEach(files, &File::name, FileRow)).selection(chosen.binding()));
```

```rust
# use std::collections::BTreeSet;
# #[derive(Clone, PartialEq)] struct Mail { id: i64, subject: String }
# let mails = State::new(Vec::<Mail>::new());
# fn show(id: i64) {}
let open = State::new(None::<i64>);          // one row
let chosen = State::new(BTreeSet::<i64>::new()); // any number of rows

elg! {
    VStack {
        ScrollView {
            LazyVStack {
                ForEach(mails, id: |m| m.id) { mail in Text(mail.subject.clone()) }
            }
            .selection_with(open, |id| show(*id))
        }
        ScrollView {
            LazyVStack {
                ForEach(mails, id: |m| m.id) { mail in Text(mail.subject.clone()) }
            }
            .selection(chosen)
        }
    }
}
```

The keys are the `ForEach`'s keys. Selection works on `VStack`, `HStack`, `LazyVStack`, and
`LazyHStack`; put it on the stack itself, so other views in the stack, like a header, aren't
rows.

It works the way people expect from their platform:

- **Clicking** a row selects it. Clicks on a control inside the row, such as a button or a toggle,
  go to the control instead.
- **The keyboard**: the stack is one Tab stop. The arrow keys move the selection, and Home and End
  jump to the ends. The selected row scrolls into view, even in a lazy stack that hadn't built it
  yet.
- **Opening** a row, with Return or a double click, calls `on_activate` with its key.
- **Several rows**: Ctrl-click (Cmd-click on a Mac) adds or removes a row, Shift-click and
  Shift-arrows select a range, and Ctrl-A (Cmd-A) selects everything.
- **Screen readers** see a list box with selectable options.

Changing the bound state selects rows from code. Keys that aren't in the list are ignored, so when
you delete an item, remove its key from the selection too.

### How selected rows look

The default row style pads each row and draws it on a rounded highlight: the accent color while
it's selected (with its text and icons in a contrasting color), a faint one while the pointer is
over it, and an outline on the row the keyboard is on. You can change its colors, corner radius,
and padding:

```cpp
list.row_style(HighlightRowStyle{{.corner_radius = 0, .padding = EdgeInsets::symmetric(16, 10)}});
```

```rust
.row_style(HighlightRowStyle::new().corner_radius(0).padding(EdgeInsets::default().horizontal(16).vertical(10)))
```

Text and icons switch color by themselves. For anything else, a row can ask whether it's
selected:

```cpp
struct MailRow {
    Mail mail;
    View body() const {
        const auto selected = Environment<RowSelectedKey>();
        return VStack({.alignment = HorizontalAlignment::leading},
                      Text(mail.subject),
                      Text(mail.sender).foreground_style([=](const EnvironmentValues& env) {
                          return env.color(selected() ? ThemeColor::on_accent : ThemeColor::secondary);
                      }));
    }
};
```

```rust
#[component]
fn MailRow(subject: String, sender: String) -> impl IntoView {
    let selected = Environment::<RowSelectedKey>::new();
    elg! {
        VStack(alignment: .leading) {
            Text(subject)
            Text(sender).foreground_style(move || {
                if selected.get() { ThemeColor::OnAccent } else { ThemeColor::Secondary }
            })
        }
    }
}
```

`PlainRowStyle` draws rows with no highlight at all, for rows that show their state themselves.
To design your own, see [Control styles](../styles/#row-styles).
