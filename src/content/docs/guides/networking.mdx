Elegance doesn't have its own HTTP or WebSocket API. Use a well-known library that you trust and
keep up to date:
<Lang only="cpp" inline>[libcurl](https://curl.se/libcurl/), [Boost.Beast](https://www.boost.org/libs/beast), or [cpp-httplib](https://github.com/yhirose/cpp-httplib).</Lang>
<Lang only="rust" inline>[ureq](https://crates.io/crates/ureq), [reqwest](https://crates.io/crates/reqwest), or [tungstenite](https://crates.io/crates/tungstenite) for WebSockets.</Lang>
Elegance gives you two things to connect it to your views:

- `post_to_ui_thread(task)` runs `task` on the UI thread, where it can change state.
- `AsyncImage(url)` downloads and shows images. See
  [Images](../images/#images-from-the-web).

## Requests on a background thread

Make requests on another thread, so the window keeps responding while you wait. When the answer
arrives, hand it back to the UI thread with `post_to_ui_thread`.

<Lang only="cpp">This example uses cpp-httplib:</Lang>
<Lang only="rust">

This example uses ureq. State can only be used on the UI thread, so Rust won't let you move it to
another thread. The [send_wrapper](https://crates.io/crates/send_wrapper) crate gets it there and
back: the callback travels to the worker thread and back in a `SendWrapper`, and is only called
once it's on the UI thread again.

</Lang>

```cpp
#include <httplib.h>

using Body = std::expected<std::string, std::string>; // the body, or why there isn't one

// `done` runs on the UI thread.
void get(std::string server, std::string path, std::function<void(const Body&)> done) {
    std::thread([=] {
        httplib::Client client(server);
        client.set_follow_location(true);
        const auto response = client.Get(path);
        Body body;
        if (!response) {
            body = std::unexpected(httplib::to_string(response.error())); // network, TLS, timeout
        } else if (response->status != 200) {
            body = std::unexpected(std::format("HTTP {}", response->status));
        } else {
            body = response->body;
        }
        post_to_ui_thread([done, body = std::move(body)] { done(body); });
    }).detach();
}
```

```rust
use send_wrapper::SendWrapper;

type Body = Result<String, String>; // the body, or why there isn't one

// `done` runs on the UI thread.
fn get(url: &str, done: impl FnOnce(Body) + 'static) {
    let url = url.to_owned();
    let done = SendWrapper::new(done);
    std::thread::spawn(move || {
        let body = ureq::get(&url)
            .call() // network, TLS, timeout, or an HTTP error status
            .and_then(|mut response| response.body_mut().read_to_string())
            .map_err(|error| error.to_string());
        post_to_ui_thread(move || done.take()(body));
    });
}
```

Inside `done`, change state as usual, and the views that show it update:

```cpp
const State<bool> loading(true);
const State<std::string> quote;

get("https://api.github.com", "/zen", [=](const Body& body) {
    quote = body ? *body : body.error();
    loading = false;
});

If([=] { return loading(); }, Progress(), Text([=] { return quote(); }));
```

```rust
# fn get(url: &str, done: impl FnOnce(Result<String, String>) + 'static) {}
let loading = State::new(true);
let quote = State::new(String::new());

get("https://api.github.com/zen", move |body| {
    if !quote.is_alive() {
        return; // the view that showed it has gone
    }
    quote.set(body.unwrap_or_else(|error| error));
    loading.set(false);
});

elg! {
    if loading.get() { Progress() } else { Text("{quote}") }
}
```

A callback can still run after the view that showed its state has gone.<Lang only="cpp" inline> Changing the state then does nothing you can see.</Lang><Lang only="rust" inline> Using the state then panics, so check `is_alive()` first, as above.</Lang>
If the work is costly, or mustn't happen once a view has gone, give the callback a flag to check,
or use your library's way of cancelling.

## WebSockets

WebSockets work the same way: run the connection on its own thread, or in your library's event
loop, and post each message to the UI thread.
<Lang only="cpp" inline>Boost.Beast and libcurl both support WebSockets.</Lang>

## JSON

Elegance doesn't include a JSON library either. Use the one you like
(<Lang only="cpp" inline>nlohmann/json, Glaze, or simdjson</Lang><Lang only="rust" inline>serde_json</Lang>),
and parse the body before you post it to the UI thread, so the window doesn't wait for it.
