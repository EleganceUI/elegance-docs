## The app and its windows

`App` is your application: its windows, its event loop, and the thread that draws. Make one, add
windows, and run it. Running returns when the last window closes, or when you call `quit()`:

```cpp
int main() {
    App app;
    app.window({.title = "Editor", .width = 1200, .height = 800}, EditorView);
    app.window({.title = "Palette", .width = 300, .height = 500}, [] { return Palette(); });
    return app.run();
}
```

```rust
# #[component] fn Editor() -> impl IntoView { elg! { Text("Editor") } }
# #[component] fn Palette() -> impl IntoView { elg! { Text("Palette") } }
fn main() -> Result<std::process::ExitCode, Error> {
    App::new()
        .window(WindowDesc::new("Editor").size(1200, 800), Editor)
        .window(WindowDesc::new("Palette").size(300, 500), Palette)
        .run()
}
```

A window's content is built once, when the window opens.

### Window options

| Option | Default | What it does |
| --- | --- | --- |
| title | `"Elegance"` | the text in the title bar and taskbar |
| width, height | 1280 × 720 | the size it opens at, in points |
| resizable | yes | whether people can resize it |
| minimum size | none | the smallest size it can be resized to |
| background | the theme's background | what shows where no view draws |
| title bar | the system's | integrated, or hidden so you can draw your own (below) |
| transparent | no | the desktop shows through where nothing opaque is drawn |
| opacity | 1 | the whole window's opacity |
| fullscreen | no | covers the whole display, without a frame |
| <Lang only="cpp" inline>material</Lang><Lang only="rust" inline>material (C++ only for now)</Lang> | none | a translucent backdrop from the system (below) |

Windows follow each display's scale, including when they move to a monitor with a different one.
Resizing is live: the content lays itself out continuously while you drag the edge.

## Your own title bar

With a hidden title bar, your content fills the whole window. Draw your own bar, mark it as the
part of the window that drags it, and add the window's buttons with `WindowControls`:

```cpp
app.window({.title = "Notes", .title_bar = TitleBar::hidden}, [] {
    return VStack({.spacing = 0},
                  HStack(Text("Notes"), Spacer(), WindowControls())
                      .frame({.height = 36})
                      .window_drag_area(),
                  Content());
});
```

```rust
#[component]
fn Notes() -> impl IntoView {
    elg! {
        VStack(spacing: 0) {
            HStack {
                Text("Notes")
                Spacer()
                { WindowControls::new() }
            }
            .frame(height: 36)
            .window_drag_area(true)
            Text("Content")
        }
    }
}

fn main() -> Result<std::process::ExitCode, Error> {
    App::new().window(WindowDesc::new("Notes").title_bar(TitleBar::Hidden), Notes).run()
}
```

Dragging the bar moves the window and double-clicking it maximizes the window, just like a system
title bar, and the controls in it still work. The window's edges still resize it.

`WindowControls` draws minimize, maximize, and close buttons in the platform's style, or a style
you choose. Wherever the system shows its own buttons, it draws nothing, so the same layout works
on every platform.

### An integrated title bar

An *integrated* title bar keeps the system's own window buttons and lets your content fill the
window underneath them. On a Mac, that's the real traffic lights over your content, and you can
move them. Platforms whose buttons can't sit over content keep their normal title bar, so your app
never shows imitation buttons where real ones exist.

The window tells you where its buttons are, so you can keep your content clear of them. It
updates as that changes, for example in fullscreen, where there are none:

```cpp
app.window({.title = "Music", .title_bar = TitleBar::integrated, .system_controls_position = Point{20, 27}},
           [] {
               const auto window = Environment<WindowKey>();
               return VStack(EmptyView().frame([=] { return Size{0, window().system_controls_frame().max_y()}; }),
                             SearchField())
                   .window_drag_area();
           });
```

```rust
#[component]
fn Music() -> impl IntoView {
    let window = Environment::<WindowKey>::new();
    elg! {
        VStack {
            EmptyView().frame_size(
                move || {
                    let controls = window.get().system_controls_frame();
                    Size::new(0.0, controls.y + controls.height)
                },
                .top,
            )
            Text("Search")
        }
        .window_drag_area(true)
    }
}

fn main() -> Result<std::process::ExitCode, Error> {
    let desc = WindowDesc::new("Music").title_bar(TitleBar::Integrated).system_controls_position(20.0, 27.0);
    App::new().window(desc, Music).run()
}
```

<Lang only="cpp">

For other differences between platforms, `current_platform()` returns `Platform::windows`,
`macos`, or `linux`, and is known at compile time.

</Lang>

### The window a view is in

A view can get its window from the environment, to close it, or to look different when the window
isn't the active one, as title bars do:

```cpp
const auto window = Environment<WindowKey>();

TitleBar().opacity([=] { return window().is_active() ? 1.f : 0.6f; });
Button("Close", [=] { window().close(); });
Text([=] { return window().is_maximized() ? "Maximized" : "Normal"; });
```

```rust
let window = Environment::<WindowKey>::new();
let (w1, w2) = (window.clone(), window.clone()); // one for each closure

elg! {
    VStack {
        Text("Title").opacity(move || if window.get().is_active() { 1.0 } else { 0.6 })
        Button("Close", move || w1.get().close())
        Text(move || if w2.get().is_maximized() { "Maximized" } else { "Normal" })
    }
}
```

A window can also be minimized and maximized from code.

## Transparent windows

A transparent window lets the desktop show through wherever its content isn't opaque. With a
hidden title bar, that makes rounded or shaped windows and see-through panels:

```cpp
app.window({.title = "Widget", .width = 340, .height = 190,
            .title_bar = TitleBar::hidden, .transparent = true},
           [] { return Widget().background(ThemeColor::surface, RoundedRectangle(16)); });
```

```rust
# #[component] fn Widget() -> impl IntoView {
#     elg! { Text("Widget").padding(16).background_in(.surface, RoundedRectangle(16)) }
# }
fn main() -> Result<std::process::ExitCode, Error> {
    let desc = WindowDesc::new("Widget").size(340, 190).title_bar(TitleBar::Hidden).transparent(true);
    App::new().window(desc, Widget).run()
}
```

<Aside>
Transparency needs a desktop that composites windows. Where there isn't one, the window stays
opaque.
</Aside>

## Translucent materials

<Lang only="rust">

The C++ API can give a window one of the system's translucent backdrops (vibrancy on macOS, Mica
and Acrylic on Windows 11). The Rust bindings don't have it yet.

</Lang>

<Lang only="cpp">

A window can have one of the system's translucent backdrops behind its content: the desktop and the
windows below, blurred and tinted, like Finder's sidebar or the Windows 11 Settings app. Where your
content and the window's background aren't opaque, it shows through:

```cpp
app.window({.title = "Files", .material = WindowMaterial::sidebar}, [] {
    return HStack(Sidebar().frame({.width = 220}),
                  Content().background(ThemeColor::background));
});
```

Each platform uses its closest match:

| Material | macOS | Windows 11 |
| --- | --- | --- |
| `sidebar` | sidebar vibrancy | Mica Alt |
| `under_window` | under-window vibrancy | Mica |
| `mica` | under-window vibrancy | Mica |
| `acrylic` | HUD window vibrancy | Acrylic |

On Windows 10 and Linux, the window stays opaque and draws its background as usual.

</Lang>
