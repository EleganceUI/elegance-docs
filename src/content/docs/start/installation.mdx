<Lang only="cpp">

In C++, Elegance is built from source with CMake, alongside your app. Its dependencies come from
[vcpkg](https://vcpkg.io), which downloads and builds them the first time you configure. Using
Rust instead? Switch the language at the top of the sidebar.

<Lang only="rust">

In Rust, Elegance is a crate. On the common platforms, Cargo downloads a prebuilt copy of the
native library, so there's no C++ toolchain to install. Using C++ instead? Switch the language at
the top of the sidebar.

</Lang>

## The fastest start

Every project in [elegance-examples](https://github.com/EleganceUI/elegance-examples) is complete
on its own. Copy <Lang only="cpp" inline>`hello-cpp`</Lang><Lang only="rust" inline>`hello-rs`</Lang>
somewhere, rename it, and build it: you have an app with a window, a component, and some state,
ready to change.

The rest of this page sets up a project from scratch.

<Lang only="rust">

## Requirements

- **Rust**, a recent stable toolchain (edition 2024).
- **Windows 10 or 11**, **macOS 13.3 or later**, or **Linux** with glibc 2.35 or later.
- `curl` and `tar`, which Windows, macOS, and Linux distributions include.
- A GPU with Direct3D 12, Metal, or Vulkan drivers.

## Create a project

<Steps>

1. Make a new binary crate:

   ```sh
   cargo new my-app
   cd my-app
   ```

2. Add Elegance to `Cargo.toml`:

   ```toml title="Cargo.toml"
   [dependencies]
   elegance = { git = "https://github.com/EleganceUI/elegance-rs" }
   ```

3. Replace `src/main.rs`:

   ```rust title="src/main.rs"
   use elegance::prelude::*;

   #[component]
   fn Root() -> impl IntoView {
       elg! { Text("Hello from Elegance") }
   }

   fn main() -> Result<std::process::ExitCode, Error> {
       App::new().window(WindowDesc::new("It works").size(400, 300), Root).run()
   }
   ```

4. Run it:

   ```sh
   cargo run
   ```

   The first build downloads Elegance's native library (`elegance_c`) for your platform and
   copies it next to your executable. Later builds reuse it from a shared cache.

</Steps>

## Shipping an app

The native library has to travel with your executable: keep it in the same folder. On Linux, also
give the executable an rpath of `$ORIGIN` so it finds the library there:

```toml title=".cargo/config.toml"
[target.'cfg(target_os = "linux")']
rustflags = ["-C", "link-args=-Wl,-rpath,$ORIGIN"]
```

On macOS, the library is already set up to load from beside the executable. Signing and
notarizing the app are up to you, as with any Mac app.

## Building Elegance from source

Cargo builds Elegance from source instead of downloading it when there's no prebuilt library for
your target, when you set `ELEGANCE_PREBUILT=0`, or when you use [previews and hot
reload](../../guides/hot-reload/), which need the shared library. A source build needs the same
tools as a C++ project (Visual Studio's C++ workload, Xcode 26, or GCC 14), and the first one takes
about half an hour. The [elegance-rs README](https://github.com/EleganceUI/elegance-rs#using-it)
lists the environment variables that control where Elegance comes from.

</Lang>

## Requirements

- A **C++23** compiler:
  - **Windows 10 or 11**: Visual Studio 2022 or later, with the C++ workload.
  - **macOS 13.3 or later** on Apple Silicon: Xcode 26 or later. (Xcode 16's standard library is
    missing `std::jthread` and `std::stop_token`, which Elegance needs.)
  - **Linux**: GCC 14 or later, with the X11 and Wayland development headers.
- **CMake 4.3** or later, and **git**. On macOS and Linux, also `pkg-config`
  (`brew install pkg-config` on macOS).
- A GPU with Direct3D 12, Metal, or Vulkan drivers.
- About 20 GB of free disk space and half an hour for the first configure, which builds Dawn,
  Google's WebGPU implementation, from source.

Ninja and vcpkg are optional: the configure fetches Ninja when it isn't installed, and uses the
vcpkg at `VCPKG_ROOT` or clones its own (into `%LOCALAPPDATA%\elegance\vcpkg` on Windows,
`~/.cache/elegance/vcpkg` elsewhere).

## Add Elegance to a project

<Steps>

1. Put Elegance in your project, for example as a git submodule:

   ```sh
   git submodule add https://github.com/EleganceUI/elegance external/elegance
   ```

2. Add it to your `CMakeLists.txt` and link `Elegance::Elegance`:

   ```cmake title="CMakeLists.txt"
   cmake_minimum_required(VERSION 4.3)
   project(MyApp LANGUAGES CXX)

   set(CMAKE_CXX_STANDARD 23)
   set(CMAKE_CXX_STANDARD_REQUIRED ON)

   # Put the app and Elegance's library in one folder, so the app finds it.
   set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)

   add_subdirectory(external/elegance)

   add_executable(my_app main.cpp)
   target_link_libraries(my_app PRIVATE Elegance::Elegance)

   if (MSVC)
       target_compile_options(my_app PRIVATE /utf-8)
   endif ()
   ```

3. Write `main.cpp`:

   ```cpp title="main.cpp"
   #include <elg/elegance.h>

   using namespace elg;

   int main() {
       App app;
       app.window({.title = "It works", .width = 400, .height = 300}, [] {
           return Text("Hello from Elegance");
       });
       return app.run();
   }
   ```

4. Configure and build. On Windows, run these from a **Developer Command Prompt** (CLion and
   Visual Studio set up the compiler for you):

   ```sh
   cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
   cmake --build build
   ```

   The first configure builds Elegance's dependencies, which takes a while. Later ones reuse them.

</Steps>

<Aside type="tip">
Compile with `/utf-8` on MSVC. Elegance's strings are UTF-8, and without the flag, string
literals with characters like `"−"` or `"…"` are mangled by the source code page.
</Aside>

If the window doesn't open, run the app from a terminal: errors are printed there, and the log
says which GPU Elegance picked.

## Build options

Set these before `add_subdirectory`, or with `-D` when you configure:

| Option | Default | What it does |
| --- | --- | --- |
| `ELG_BUILD_SHARED` | `ON` | Build Elegance as a shared library. `OFF` links it into your app; [hot reload](../../guides/hot-reload/) needs `ON`. |
| `ELG_ICONS` | `ON` | Embed the Phosphor icon set (regular, bold, and fill; about 1.4 MB). |
| `ELG_ICONS_EXTRA_WEIGHTS` | `ON` | Also embed Phosphor's thin, light, and duotone styles (about 1.6 MB). |
| `ELG_ACCESSIBILITY` | `ON` | Screen reader support, through AccessKit. |
| `ELG_BUILD_SANDBOX` | top level | Elegance's sandbox app and, in a shared build, the hot reload host. |
| `ELG_BUILD_TESTS` | top level | Elegance's unit tests (needs the vcpkg `tests` feature). |

## Linking statically

Turn off `ELG_BUILD_SHARED` before adding Elegance, and it's linked into your app instead of
shipping beside it:

```cmake title="CMakeLists.txt"
set(ELG_BUILD_SHARED OFF CACHE BOOL "" FORCE)
add_subdirectory(external/elegance)
```

Its dependencies (SDL, Dawn, FreeType, HarfBuzz) are still shared libraries with vcpkg's default
triplets, and they're copied next to your app.

### A single executable on Windows

With vcpkg's `x64-windows-static` triplet, the dependencies and the C runtime are static too, and
the app needs nothing beside it but Windows. Elegance notices the triplet and builds itself static
to match. An app comes to about 20 MB.

Because vcpkg reads only the top-level project's manifest, your project then lists Elegance's
dependencies in its own `vcpkg.json`:

```json title="vcpkg.json"
{
  "name": "my-app",
  "version": "0.1.0",
  "dependencies": [
    "freetype",
    "harfbuzz",
    "miniaudio",
    { "name": "msdfgen", "default-features": false },
    { "name": "stb", "platform": "!windows" },
    "sdl3",
    "dawn"
  ]
}
```

and configures with vcpkg's toolchain and the triplet:

```sh
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release ^
      -DCMAKE_TOOLCHAIN_FILE=%VCPKG_ROOT%/scripts/buildsystems/vcpkg.cmake ^
      -DVCPKG_TARGET_TRIPLET=x64-windows-static
```

`dxcompiler.dll` and `dxil.dll`, the DirectX shader compiler, are optional beside such an app.
Without them Direct3D 12 compiles shaders with the older FXC, and the first frames take longer.

## Working on Elegance itself

To build Elegance's own sandbox and tests, clone it and use one of its CMake presets
(`windows-debug`, `macos-debug`, `linux-debug`, and their `-release` versions):

```sh
cmake --preset macos-debug
cmake --build build/macos-debug
./build/macos-debug/bin/sandbox
```

The macOS presets target macOS 13.3, and build vcpkg's dependencies for the same version with the
overlay triplet in `cmake/triplets/`. If a build warns that dependencies were built for a newer
macOS, configure again with the preset: that rebuilds them.
