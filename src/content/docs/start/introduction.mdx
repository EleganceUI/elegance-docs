Elegance is a framework for building desktop app interfaces. You describe what the screen should
show as a tree of small views, adjust them with modifiers, and connect them to state. When the
state changes, Elegance updates exactly the parts of the screen that depend on it, and a GPU
renderer draws the result.

You can write Elegance apps in **C++23** or **Rust**. Both use the same views, modifiers, and
ideas, so everything in these docs applies to either; the switch at the top of the sidebar picks
which language the samples are in.

```cpp
#include <elg/elegance.h>

using namespace elg;

int main() {
    App app;
    app.window({.title = "Hello"}, [] {
        return VStack(Image("hand-waving").font(Font::system(48)),
                      Text("Hello, Elegance!").font(Font::title));
    });
    return app.run();
}
```

```rust
use elegance::prelude::*;

#[component]
fn Hello() -> impl IntoView {
    elg! {
        VStack {
            Image("hand-waving").font(Font::system(48.0, .regular))
            Text("Hello, Elegance!").font(.title)
        }
    }
}

fn main() -> Result<std::process::ExitCode, Error> {
    App::new().window(WindowDesc::new("Hello"), Hello).run()
}
```

## Why Elegance

The easiest way to build a good-looking desktop app today is to ship a web page inside a browser
engine, and pay for it in memory, startup time, and battery. Classic native toolkits are lean but
slow to work with. Elegance aims for the best of both:

- **Pleasant to write.** You compose views and chain modifiers, the way SwiftUI does it. Layout,
  appearance, and behavior sit together in ordinary code: there's no markup language to learn and
  no scripting layer in between.
- **Reactive at the core.** State is a first-class value. Change it, and the text, color, or list
  that reads it updates by itself. Nothing is diffed and nothing else is rebuilt.
- **Light.** Apps start in well under a second, use no CPU while idle, and fit in tens of
  megabytes of memory.
- **Complete.** Text editing, lazy lists, grids, menus, popovers, animation, themes, images,
  audio, video, the camera, desktop integration, accessibility, and hot reload are built in.

## What it looks like

A view is a value. You build bigger views out of smaller ones, and modifiers return new views, so
they chain:

```cpp
View ProfileBadge(std::string name) {
    return HStack(Circle().fill(ThemeColor::accent).frame(32, 32),
                  Text(std::move(name)).font(Font::headline))
        .padding(12)
        .background(ThemeColor::surface, RoundedRectangle(12));
}
```

```rust
#[component]
fn ProfileBadge(name: String) -> impl IntoView {
    elg! {
        HStack {
            Circle().fill(.accent).frame(32, 32)
            Text(name).font(.headline)
        }
        .padding(12)
        .background_in(.surface, RoundedRectangle(12))
    }
}
```

State is a small handle you can copy into closures. Reading it inside a closure subscribes that
closure to it, so the closure runs again whenever the value changes:

```cpp
const State<bool> on(false);

VStack(Toggle("Notifications", on),
       Text([=] { return on() ? "You'll be notified" : "Muted"; }));
```

```rust
let on = State::new(false);

elg! {
    VStack {
        Toggle("Notifications", on)
        Text(move || if on.get() { "You'll be notified" } else { "Muted" })
    }
}
```

<Lang only="rust">

The Rust API is a thin, safe layer over the same library. `elg!` is a macro that turns the
layout-shaped syntax above into ordinary builder calls, so anything you can write in it you can
also write by hand.

</Lang>

## Platforms

Elegance runs on **Windows 10 and 11**, **macOS 13.3 or later**, and **Linux** with X11 or
Wayland. It draws with WebGPU (through Google's Dawn), which uses Direct3D 12 on Windows, Metal on
macOS, and Vulkan on Linux. System features such as notifications, file dialogs, the camera, and
video playback use each platform's own services.
